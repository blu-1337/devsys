Baseline: last full verification on 2026-11-24 (D = today). Local CLI is 2.1.331. The capabilities header still says 2.1.310. One research pass covered changelog 2.1.312 to 2.1.331 plus models (budget unknown, so research ran one pass at a time).

## Summary
- Nothing breaks devsys. All 6 agents pin `model` and `effort`, and no skill declares `allowed-tools`, so the new subagent, effort and `/loop` rules don't affect it.
- A new model came out: **Fable 5.2** (`fable` alias, CLI 2.1.321 or later). Pro plan limits don't cover it (it uses pay-as-you-go credits), and it costs twice as much as Opus.
- Some local facts are stale: the always-on token cost, the `plugin details` invocation, the plugin CLI list and the header version.
- Prune: none. The always-on cost (~936 tok) is modest. Evals showed the SessionStart nudge is needed. No eval evidence shows any skill is redundant.

### 2. Fix: make the `plugin details` call work for an uninstalled source repo
- **Change:** Replace `claude plugin details devsys` with `claude --plugin-dir <sourceRepo> plugin details devsys`. `--plugin-dir` is a global flag, so it goes before `plugin`.
- **Why:** `claude plugin list` reports "No plugins installed", and the plain command fails with `Plugin "devsys" not found`. Putting `--plugin-dir` after `details` gives "unknown option". (Observed locally.)
- **Files:** `skills/update/SKILL.md` (step 1), `update/sources.md` (Local line), `update/capabilities.md` row 47 source
- **Risk:** none
- **Token impact:** about +5 tok on invoke
- **Kind:** fix

Also note that `--plugin-dir` is global. Change the header to "Claude Code 2.1.331".

### 4. Fix: note how a skill's `model:` now affects subagents
- **Change:** Extend the "Skill `model:` override" row: since 2.1.330, a skill that sets `model` keeps the subagents it spawns on the **session** model. Unpinned agents therefore no longer follow the skill's model. This is fine for devsys, because all agents pin `model` and the `Explore` override pins haiku. It reinforces the "always pin" rule (row 29).
- **Why:** Changelog 2.1.330, https://code.claude.com/docs/en/changelog
- **Files:** `update/capabilities.md`
- **Risk:** none
- **Token impact:** 0
- **Kind:** fix

### 5. Adopt: record Fable 5.2 as explicitly not used on Pro
- **Change:** Add a routing row: `fable` (Fable 5.2, `claude-fable-5-2`), **not used**. It falls outside Pro limits and draws on paid credits. It costs $8/$40 per MTok, against $4/$20 for Opus 5.5. Its default effort is high. Opus stays the planning model.
- **Optional add-on:** the session-start hook warns once when the statusline model id contains "fable". It costs about 20 tok, and only when triggered.
- **Why:**
  - https://platform.claude.com/docs/en/models/fable-5-2/overview
  - https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan (credits only on Pro)
  - The launch offer ended on 2026-11-16: https://support.claude.com/en/articles/17506494-claude-fable-5-2-launch-offers
- **Files:** `update/capabilities.md`. With the add-on, also `hooks/win/session-start.ps1` and its tests.
- **Risk:** low. The add-on touches a hook that already has uncommitted changes, so merge with care.
- **Token impact:** 0, or about 20 tok when the warning fires
- **Kind:** adopt

### 6. Adopt (low value): declare a minimum CLI version in plugin.json
- **Change:** Add `"engines": { "claude-code": ">=2.1.321" }` to `.claude-plugin/plugin.json`. Check that `claude plugin validate .` accepts this syntax before committing.
- **Why:** The field was added in 2.1.323 (https://code.claude.com/docs/en/changelog). The hooks, the eval runner and the `fable` alias rely on recent behaviour. The value is small because the CLI auto-updates on channel "latest".
- **Files:** `.claude-plugin/plugin.json`
- **Risk:** low. If a CLI older than 2.1.323 rejects unknown fields, drop this item.
- **Token impact:** 0
- **Kind:** adopt
